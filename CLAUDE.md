# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Personal, local-first MTG collection and spending tracker. A SQLite database is the source of truth for money and card ownership. It is deliberately not a deckbuilder or a card scanner. See README.md for the roadmap and the known gaps from the first real import.

## Architecture

**Data flow:** `mtg import-order` → `importers/order_wallet.py` (Apple Wallet `.order` zip → `transactions` + `products` + content-addressed `receipts/<sha256>.order`) → for each product, `importers/precon_decklist.py` matches `display_name` against `seed/precon_decklists/*.json`. On a match it resolves the list against Scryfall, creates a deck with one `lots` row per physical card (all equipped), and calls `allocation.allocate()`.

**Schema:** `mtgtracker/migrations/NNNN_*.sql`, applied in order by `db.migrate()`. Progress is tracked with `PRAGMA user_version`, which equals the count of applied files. Add new migrations as new numbered files and never edit applied ones. The `cl_%` write-log triggers are generated by `db.migrate()`: never hand-write, edit, or drop them (see Safety net). There is no ORM. All reads and writes are explicit SQL in each module. `models.py` holds plain dataclasses only, and connections use `sqlite3.Row`.

**Key invariants (don't break these):**
- **Money is integer cents.** Parse amounts with `money.parse_cents` (Decimal, raises on fractional cents). Never use floats. Every split goes through `money.largest_remainder_split`, so totals reconcile exactly with a deterministic tie-break by index.
- **Order import reconciles or raises.** Subtotal + tax + shipping must equal the total, and the line items must sum to the subtotal. Tax and shipping are allocated pro-rata into each product's `cost_basis_cents`. Re-import is idempotent by receipt sha256. Transactions upsert on `(order_type_identifier, order_identifier)` and only when the incoming `updatedAt` is newer. Products are created only on first insert.
- **One lot = one physical card.** Quantities are never collapsed. Cost basis is split evenly by lot count, not by card value. `allocate()` raises `AlreadyDisposedError` if any lot in the product has a disposition.
- **Wanted cards are never lots.** A deck's list is its `deck_cards` rows (copies you own, equipped here or elsewhere) plus its `deck_wants` rows (migration 0004): cards you don't own yet, one row per copy, "to acquire". Never create lots or transactions for unowned cards. Wants stay out of `/cards`, collection totals, and cost basis, but every reader of a deck's list must include them: display groups (`queries._wanted_rows`, `wanted=True`), identity, breakdown, counts, version snapshots (`deck_version_wants`), the commander check in `apply_changes`, and import skips.
- **Deck membership vs. physical location:** a `deck_cards` row means the card is on that deck's list. `equipped=1` means the deck physically holds it, and a partial unique index allows only one equipped deck per lot. `add_to_deck(equipped=True)` unequips the card elsewhere first. `borrow` moves `equipped`, `cut` deletes the row, and `assembly.plan` sorts cards on a deck's list that aren't equipped there (see "Deck assembly"). `decks.reassemble` remains as the low-level query tests use.
- **Resolution is honest, not guessed.** A card name with multiple printings in the set (e.g. Sol Ring, Arcane Signet in `fdc`) is reported as ambiguous. Such cards, not-found names, and basic lands still get lots, but with `scryfall_id` NULL. The commander is expected to be foil.
- **Seeding is recoverable.** `seed_precon_deck_for_product` is a no-op if the product already has lots. `import-order` always attempts seeding, so re-running it recovers from a failed Scryfall fetch.

**Web UI** (`mtgtracker/web/`): FastAPI + Jinja2, server-rendered, with no JS build. It is one CSS file with light/dark tokens. The file is linked as `style.css?v=<content hash>` via `static_version()`, and `/static` responses get `immutable` when versioned and `no-cache` otherwise. Reference any new static file the same way, or browsers will keep a stale copy. `create_app(db_path)` runs migrations once. Each request opens its own connection with `check_same_thread=False`, because FastAPI's threadpool may create it on one thread and use it on another. Never share a connection. Page-only read SQL lives in `web/queries.py`. Money renders only through the `money` Jinja filter (`format_cents`, integer math). Never serve `receipts/`, since those files contain credentials. Page loads never call the Scryfall API. The only network fetch is the explicit "look up set" POST, which goes through the cached `fetch_set_cards`. Card images are hotlinked from Scryfall's image CDN (intentional). They're looked up through `mtgtracker/cardinfo.py`, which indexes `scryfall.cached_cards()`, a parse of every cached set that's memoized until the cache files change. Pinned lots show their exact printing. Unpinned lots show a representative printing flagged `exact=False`: one that matches the lot's finish and isn't a promo. `cardinfo` also sorts cards into deck sections by type line and supplies mana value (`cmc`). Deck grids show a Commander section first, using `decks.commander` (added in migration 0002 and set by seeding), then the type sections. Deck and card lists order by mana value, highest first. Among equal mana values, colored mana outranks colorless: more distinct colors, then more colored symbols ({1}{U}{R} > {1}{R}{R} > {3}; `cardinfo.color_weight`). Name breaks remaining ties. Decks and cards default to an image grid, and `?view=list` gives the table. Tiles have no captions. On `/cards`, a disposed card is greyed out with the `.away` class. On deck pages, tiles and rows carry `.in-deck` and are never greyed: `.away`/`.wanted` stay as classes and in the panel's "where", and the CSS dimming is scoped to `:not(.in-deck)`. Unpinned non-basics get a "needs printing" flag (on deck pages, the corner mark instead: see below).

**Code layout (web):**
- **`web/app.py`** holds the Jinja environment (filters, globals) and `create_app(db_path)`. It runs migrations once and puts `db_path`, `auth`, `verifier` and `templates` on `app.state`; `/healthz` and the dev-only `/dev/as/{id}` live there. Routers are added with `include_router`; FastAPI 0.141 nests them lazily, so `app.routes` holds `_IncludedRouter` objects rather than flat paths (walk `original_router` to list them).
- **`web/middleware.py`** installs `identify`, the static cache headers and the cross-origin write rejection, in that order.
- **`web/deps.py`** has everything request-level, importable by any router: `get_conn`, `me`, `render`, `redirect`, `form_int`, and the guards `load_deck` / `require_own_deck` / `require_own_lot` / `load_person` / `may_act_for` / `may_add_people`. Nothing is closed over; it reads `request.app.state`.
- **`web/routes/`** has one `APIRouter` per area: `pages` (home, transactions, collection), `decks`, `modify`, `assemble`, `exports`, `people`, `printings`, `purchases`. Handlers stay thin: parse the request, run the guards, call a service, render or redirect.
- **`web/api/v1/`** is the JSON API (see "JSON API"): `common` (errors, the `write` wrapper), `meta`, `decks`, `cards`, `people`, `purchases`, `assembly`. `install(app)` includes the routers with prefix `/api/v1`.
- **`mtgtracker/services/`** is the non-HTTP write logic (`decks`, `modify`, `people`, `printings`, `exports`, `collection`): plain functions over `conn` and typed arguments that return the notice text and raise `ServiceError` (message safe to show) or `NotFoundError`. Guards stay with the caller and run first.
- **Callers own transactions.** Every write function takes `commit: bool = True`, covering the `deckmods` change-list edits, `import_list`, `create_deck_from_list` and `apply_changes`, `commanders.set_commander`, `printings.assign`, `users.create`, `collection_csv.import_collection` and the services above. With `commit=False` it does all its validation and writes but never commits or rolls back. The default commits on success and, for the multi-statement ones, rolls back on error. A dry run is the `commit=False` call followed by `conn.rollback()`, so there is one validation path (`tests/test_commit_split.py`).

**Design:** a printed deck-sheet look. Avoid generic "app" styling: no purple, no boxed cards, no pill tags, no rainbow charts.
- **Surface and type:** warm paper (`--bg`), ink text, and `--font-display` (Spectral from Google Fonts, falling back to Georgia) for the wordmark, headings, and headline numbers. The body uses the system sans.
- **Structure:** sections are separated by rules, not boxes. `h2` is the serif heading over a hairline. `h3` labels are uppercase, tracked, and in the accent. Headline numbers are a ledger row (`.stats` / `dl.ledger`). Tags are squared small caps. Corners use `--radius` (4px); card images keep their own card-shaped radius.
- **Deck color themes:** `cardinfo.deck_identity()` gives a deck's colors, from the commander's color identity or otherwise every non-land card's colors. `queries.deck_identities()` computes all decks in one query.
  - On deck, modify, and version pages, the `theme_attrs(identity)` Jinja global sets `data-identity`, `--accent: var(--ink-X)`, and `--identity`, a hard-stop stripe of all the colors, on `<body>` via the `body_attrs` block.
  - The header's bottom edge becomes that stripe, and so do the strong rules: the ledger, the chart columns, and the list section heads. They're drawn as a 2px background line, so hairlines stay hairlines.
  - Links, buttons, section labels, the mana curve, and list-row tints follow `--accent` (the first color). Card-type bars use `--accent-2` (the last color), so a two-color deck shows both in its data. A one-color deck sets both to the same ink.
  - `identity_pips()` renders the colors as mana symbols.
  - `--ink-*` colors are text-safe on `--bg` in both modes. Other pages use the neutral `--ink-C`.

**Deck page order:** header, ledger (on list, here, away, to buy, borrowable, cost basis for the owner), action bar (`.deck-actions`: Assemble primary when there is work, Modify, Export; Assemble and Modify owner-only), notes summary (owner-only `<details>`, one line with the first note line), collapsed breakdown, the cards, then `.deck-secondary` (pull list, borrow/acquire checklists).

**Deck breakdown and list view:** the deck page has a collapsed-by-default breakdown (a `<details>`, one summary line, between the notes and the cards) built by `web/breakdown.py` from the display groups: a mana curve of non-land cards, mana colors (each non-land card counted once, with Multicolor and Colorless buckets), and card types. It's plain HTML with no chart library. Mana colors use the `--mana-*` tokens, the dataviz skill's validated categorical hues mapped to mana meaning; re-run `validate_palette.js` if you change them. **Color buckets** are `breakdown._color_key`:
- a card's own color(s) in WUBRG order: "R", or "UR" for a multicolor card, labelled "Blue-Red"
- `C` for colorless
- `X` when the colors aren't cached

Each bucket carries a CSS `fill` (`_fill`), which templates use as inline `background` for segments and swatches alike: the `--mana-*` hue for one color, 135° stripes of each color for a combination, and hatched gray for `X`.

**One-color decks** draw the mana curve in `--accent` and card types in `--accent-2`, as plain bars. **Decks with two or more colors** (`deck_breakdown(groups, identity)` → `stacked`) split both charts by color bucket: curve bars bottom-up, type bars left to right. Both use 2px gaps, per-segment tooltips, and their own counted legend.

`cardinfo.lookup` treats an uncached basic land as known (colorless, cmc 0, "Basic Land — X"). (`TYPE_SLOTS`/`--series-N` remain in the data for a categorical view, but nothing renders them now.) Legends always show counts, so color never carries meaning alone. The list view (`?view=list`) is two CSS columns of type sections, each row showing qty, name, and cost via the `mana_symbols` Jinja filter. Rows carry `data-card` for the panel.

**Sorting and filtering:** this is a shop-style sidebar on deck pages and `/cards`, for both views, built by `facet_sidebar` and `results_bar` in `_card_tiles.html` inside a `.catalog` grid.
- **Filtering logic:** `web/filters.py` (`CardFilters`) handles the multi-value GET facets `color`, `type`, `mv`, and on `/cards` also `deck`, plus `sort` and `color_mode`.
  - Within a facet, values are OR'd. The exception is color with `color_mode=all`, where they're AND'd. Facets are AND'd with each other.
  - Type matching uses every type on the type line (`CardInfo.type_labels`), so an Artifact Creature matches both Artifacts and Creatures. Display sections still use one `category` each.
  - `facet_counts` counts each facet with the other facets applied, not itself.
  - `parse()` drops unknown values, and `href()` keeps the current filters and view in links.
- **Page behavior:**
  - The Sort select sits in the results bar and belongs to the form via `form="facet-form"`.
  - `static/filters.js` submits on every change and drops empty or default params.
  - Below 900px the sidebar is a "Filters" disclosure that is always folded by default. An inline script right after the `<details>` does this before first paint, so the sidebar doesn't flash open.
  - At 600px and below, the header nav wraps. Keep every page free of horizontal page scroll down to 390px wide.
  - On deck pages, filters narrow only `sections`. The counts, breakdown, and commander picker always cover the whole deck.
  - On `/cards`, filters run on individual copies first, then `queries.collapse_by_name` merges copies of the same card into one row, whatever their deck or printing, with a `where`/`printing`/`finish` summary for the panel.

**Layout:** `base.html` wraps `main` and the panel in `.page`. On wide hover-capable screens, that becomes a centered grid of the content column plus a 356px sticky panel. `--content-max` (1040px, or 1284px on `.wide` catalog pages to fit the 220px sidebar) sets the content width.

**Deck versions and modifications:** `mtgtracker/deckmods.py`, migration 0003, and `/decks/{id}/modify`.
- **Versions:**
  - `decks.version` is the current version. 0 means never recorded, e.g. a bare `create_deck`.
  - `decks.record_version()` bumps it and snapshots the whole list into `deck_version_cards`. Seeding records v1 after the lots exist, and the migration backfilled existing decks as v1.
  - Diffs are computed between consecutive snapshots.
- **Changes:** `deck_changes` rows insert a card, optionally replacing (`cut_lot_id`) a card on the list.
  - An owned insert references a lot, which may be listed in another deck; applying it borrows that copy.
  - A planned insert has `add_lot_id` NULL and is found by `scryfall.fetch_named_card`, which caches to `CACHE_DIR/cards/`, is included in `cached_cards()`, and is never a set.
- **Applying:** `apply_changes()` applies every pending change as one version, all or nothing. It validates the batch first, then writes in one transaction without using the committing `decks.*` helpers.
  - Owned inserts are equipped here (borrowed if another deck held them).
  - Planned inserts become `deck_wants` rows.
  - Replaced cards leave the list and become unassigned.
  - The commander is cleared only when no copy of it remains, owned or wanted.
- **New deck from a list:** `deckmods.create_deck_from_list` backs `POST /decks/new`. It resolves on Scryfall first, then writes the deck, owned copies (`equipped=0`, so the deck starts unassembled and nothing moves), wants, the commander from the list's Commander section (`Entry.commander`, owned or not), and the v1 snapshot in one transaction. The deck page tags three states: here, `.away` (owned, in another deck), and `.wanted` (not owned; "To acquire" flag), all drawn as normal cards. Assembly (see "Deck assembly") sorts it into fill/swap/pull/borrow/acquire lines. Version diffs compare card-name multisets, so acquiring a wanted card won't show as a change.
- **List import:** `importers/decklist_text.py` parses Moxfield/Archidekt/Arena text: an optional qty or `Nx`, `(SET) number`, `*F*`/`*E*`, and section headers, with sideboard-like sections skipped. `deckmods.import_list` resolves names through `scryfall.fetch_collection` (POST `/cards/collection`, 75 per batch, cached per card, with up to 10 fuzzy retries). It skips copies already in the deck or queued, so re-imports are harmless, uses free owned lots first (unassigned before borrowed), queues the rest as planned, and writes all of it in one transaction.
- **Modify page UI:** each change shows the card to add and the card it replaces as readable `card_face` tiles, a link-free tile macro that can sit inside a button, with panel data.
  - The replacement picker (`#cut-picker`) is rendered once and moved under whichever change opens it by `static/deck-modify.js`. It shows the deck's cards as tiles grouped by type, with hover/panel, and clicking a tile submits that change's `/cut`.
  - Without JS, each change falls back to a `<noscript>` `<select>`.
  - Don't render a picker per change: 40+ queued changes would mean thousands of tiles.
- **Replacing cards you don't own:** a change can cut a `deck_wants` row (`cut_want_id`, migration 0005, deliberately with no foreign key because apply deletes the want) instead of a lot.
  - `add_swap` queues "add this owned copy, replacing that wanted card".
  - `wanted_groups` lists the deck's wants, holding back copies already being replaced.
  - `owned_fitting` lists insertable owned cards whose color identity fits the deck's colors. Colorless fits, and uncached cards are offered too.
  - On the Modify page, the "Cards you don't own" section shares one `#own-picker`, rendered once and moved by `deck-modify.js`, which puts the clicked card's type section first. The `#cut-picker` also offers wanted cards via `cut_want_id`.
- **Known gap:** lots come only from precon seeding and collection imports, so there's no purchase flow yet to turn a wanted card into an owned one.

**Ownership marks (deck pages):** tiles carry nothing over the card text. A small disc sits on the top-right corner, half outside the card (`.tile-own`, a sibling of the clipped `.tile-art`): filled ✓ = in this deck, outlined ✓ = yours but elsewhere, dashed ring = yours with no printing picked (links to `/printings/{lot}`), an initial = a friend has it (tooltip names them), nothing = still to buy. `/cards` and Modify keep the `.tile-flag` labels.

**Card size:** the grid's `--tile-min` (190px) is the smallest readable card width. The grid drops a column rather than shrinking cards: 5 across when the results area is 1008px, 4 at 1600px with the panel showing. Phones use 140px for 2 columns.

**Card details panel:** on wide screens with a mouse (`(hover: hover) and (min-width: 1480px)`), hovering or focusing a card shows a sticky detail panel on the right. Everywhere else, including phones, tablets, and narrow windows, tapping a card or pressing Enter/Space on it opens the same content in a modal `<dialog>` sheet (`#card-dialog`, a bottom sheet on phones). Taps on links and controls inside a card keep their normal behavior. Both are driven by `static/card-panel.js`, whose `render()` builds the content for either. In both, the Decks row lists every deck whose list has the card, as `1× Deck` links. When there's more than one deck, the one that holds the card is labeled current (`queries._decks_for`, merged by `_merge_decks` on `/cards`). The sheet animates: it slides up and down on phones, and lifts and fades on wider screens. The open animation is pure CSS. Closing adds `.closing` and waits for `animationend` before `dialog.close()`, and this covers Escape (`cancel`), backdrop taps, and swipe-down. There's no close button. On phones, dragging the sheet down once its content is scrolled to the top moves it with the finger. Release past about a third of its height, or flick faster than 0.5 px/ms, to close; otherwise it snaps back. Swiping sideways steps to the next or previous card, and so do the arrow keys in the sheet. The order is the page's `.tile[data-card]` or `.deck-row[data-card]` elements, so it follows the current sort and filters, and a position counter shows where you are. The first ~8px of movement decides between sideways and vertical. At either end of the list the sheet resists and springs back. It's instant under `prefers-reduced-motion`. When the pop-up has a card image, it hides the repeated name, type, and rules text of the face the image shows (`.card-panel-art[data-face]`), via CSS. Placeholder cards keep their text, and the desktop panel always shows it.

**Double-faced cards:** `CardInfo.back_image` is the second face's image, set only when each face has its own image (transform, modal, reversible). Split, adventure, and flip cards print both halves on the front, so they get none.
- **Flip buttons:** the `tile` macro adds a `.tile-flip` button with `data-front`/`data-back`, and the panel and sheet add `.card-panel-flip`.
- **Behavior** (all in `card-panel.js`): flipping toggles `aria-pressed` and turns the image with a short scaleX animation, waiting at most 1.2s for the other image to load. It's instant under reduced motion. A flipped tile (`.flipped`) opens the panel or sheet on its back face, and the panel follows a tile flipped under it.
- **Not in `card_face`:** it can sit inside a button, so it has no flip button; the panel's covers it. Every tile and list row carries `data-card='<json>'`, built by the `panel_json` macro in `_card_tiles.html` from `CardInfo` (faces, rarity, set, artist) plus the row's location and cost. The script builds DOM nodes with `textContent`, never `innerHTML`, and turns `{X}` into Scryfall mana-symbol SVGs. The panel's image slot has a fixed aspect ratio so the text doesn't jump while images load. Pages opt in with `{% block body_class %}with-panel{% endblock %}` plus the `panel` block.

**Users and sign-in** (migration 0006, `mtgtracker/users.py`, `web/auth.py`):
- **Ownership:** every lot, deck and transaction has `owner_id` (existing rows belong to user 1, the original owner and an admin). `lots.transaction_id` is nullable, so a card can exist without a recorded purchase.
- **Auth mode** comes from `MTG_AUTH`: `single` (default; everyone is user 1, as before), `dev` (local only; `/dev/as/{id}` sets a cookie), or `cloudflare`.
  - In `cloudflare` mode, the Access JWT (header or `CF_Authorization` cookie) is verified with RS256 against the team's keys, checking `aud` (`CF_ACCESS_AUD`), `iss` (`https://CF_ACCESS_TEAM_DOMAIN`) and `exp`.
  - Its email must match an existing user: an allowlist, never auto-created. `MTG_OWNER_EMAIL` claims user 1 on its first sign-in.
  - The app is the only allowlist. The Access application's Allow policy is "Everyone" (one-time-PIN verified email), plus a Service Auth policy for the `claude-mtgtracker` service token. So adding someone at `/people` is enough to let them in, and a verified stranger gets the 401 "ask the owner to add you" page before any data.
  - Loopback clients act as user 1 so port-forward works. That's only safe because uvicorn runs with `proxy_headers=False` and cloudflared runs in its own pod.
  - Anything else gets the 401 `signed_out.html`. `/static/` and `/healthz` (the k8s probes) need no identity.
- **Scoping:** `request.state.user` is set by the `identify` middleware. List queries take an `owner_id`.
- **Visibility:** friends can view each other's decks, deck versions, `/people/{id}` and `/people/{id}/cards`, with `can_edit=False`, so there's no Modify, commander picker, printing links or cost-sort.
  - Money stays private: someone else's lot shows cost `None`, a deck's cost basis shows only to its owner, and another user's transaction is a 404.
- **Write guards** (`web/deps.py`): every write route calls `require_own_deck` / `require_own_lot` on every id it's posted (403). `deckmods`' candidate and free-lot queries offer only the deck owner's lots, and `_check_insertable` refuses others' lots too.
- **Acting for others:** `users.can_act_for` lets an admin act for someone who has never signed in. `deps.may_act_for` also allows any system actor to act for any enabled person (collection imports), since it could send that person as `X-Act-For` anyway.
- **Admins:** an admin adds people at `/people`, but only in `dev`/`cloudflare` mode. In `single` mode every visitor is the admin, so the web can't touch the allowlist there; use `mtg add-user`.
- **System users** (migration 0008, `users.kind='system'`): an automated actor (Claude) that acts for people. It has no email and is never an admin (`by_email`/`claim_owner` ignore it, and triggers enforce it), so the email path can't reach it. `disabled_at` refuses a user (person or system, never user 1) at sign-in with the 401 page.
  - **Credentials:** `service_credentials` maps a Cloudflare Access service token's **Client ID** to a system user (revocable, `last_used_at`). Only the Client ID is stored; never accept or print a secret. In `cloudflare` mode a service token's JWT has no email, so `AccessVerifier.verify` returns the `common_name` (same RS256/aud/iss/exp checks); an email wins if both are present; neither is refused. Unknown, revoked or disabled credentials are 401. In `dev` mode only, `X-Dev-Service: <client id>` takes the same path.
  - **Principal vs. actor:** `resolve()` returns `(principal, actor)`. `request.state.user` is the principal (whose things are touched, so every guard, money-visibility and `can_edit` check is unchanged); `request.state.actor`/`deps.actor()` is who really asks. A system actor must send `X-Act-For: <user id>` (missing or unknown is 400, a disabled or system target is 403); a person sending it gets 403 in every mode. The principal is never `touch`ed, so acting for someone doesn't make them "signed in". System requests get JSON `{"error": {code, message}}`; people get plain text.
  - **Carte blanche, within the principal:** a system actor can do anything the principal could. Human-only routes use `Depends(require_person)` (credential/system-user admin under `/system-users/...`, `/dev/as`); admin pages also need `may_manage_system` (not in `single` mode). Never give a system actor those.
  - **Risky actions** are `@risky` routes that call `deps.run_risky(request, conn, operation, form)`, where `operation(conn)` runs a service with `commit=False` and returns `(result, preview)`. A person just gets it done. A system actor without `confirm` gets 409 `confirm_required` with the preview and a token (rolled back); with one, the operation is re-run and committed only if its fresh preview digest equals the token's, else 409 `preview_changed` (or `confirm_invalid` for a bad, expired or mismatched token). Tokens (`mtgtracker/confirm.py`) are HMAC-signed over actor, principal, method, path, params and preview digest, last 15 min, are single-use (`confirm_used` on replay), and die on restart (`MTG_CONFIRM_SECRET` pins the key). The operation runs twice when confirmed, so it must only touch the DB (no files or network). Add every new risky route to `RISKY_SAMPLES` in `tests/test_system_user.py`, which fails if a `@risky` route is missing.
  - **Audit:** each successful write (status < 400, no `error=` redirect) has one `audit_log` row (actor, principal, method, path, endpoint name, path params, notice or preview, `restore_point`). It's reserved inside the write's transaction (`deps.reserve_audit`, see Safety net) and the `identify` middleware fills in the summary afterwards on its own connection; a failure is logged and swallowed. It's shown as "Recent activity" on `/people/{id}` to that person and admins, never to friends.
- **Profile** (`/profile`, `GET /api/v1/profile`, `PUT /api/v1/profile`): the principal edits their own display name (`users.clean_name`: trimmed, 1 to 60 characters). The sign-in email, role and member-since are read-only. Any person in any mode, and a system actor may rename the person it acts for (not risky, audited as "Renamed A to B"). `identify`'s audit notice prefers `request.state.audit_notice` over the redirect's "Saved.".
- **Admin edit** (`/people/{id}/edit`, human-only, `may_manage_system` so not in `single` mode; system actors get 403): name and sign-in email, which decides who can sign in as that person. Email must be valid and unique (NOCASE), is never editable on your own account or a system user's, and for someone who has signed in needs the confirm checkbox (re-checked server-side). No email change over the API; `mtg set-email` at the console. The audit summary says "Changed X's sign-in email" and never the address.
- **`can_edit` fails closed:** `render()` defaults it to False, and pages pass True only when the viewer owns what's shown. Gate every new owner-only control on it.

**Friends' copies (borrowable):** `queries.FriendCopies(conn, exclude)` indexes every non-disposed lot owned by someone not in `exclude`. It's keyed by normalized name and front face (`_name_keys`), so "Delver of Secrets" matches a "Delver of Secrets // Insectile Aberration" lot. Calling it with a card name returns `[{id, name, qty, where}]` per friend.
- **Who's excluded:** `get_deck` excludes the deck owner and the viewer. The Modify page excludes you.
- **Display:** groups get `friends`.
  - A wanted card a friend owns becomes `.borrowable`, flagged "From Alex" (or "From N friends"), with the tooltip `borrow_summary()` ("Owned by 1 friend: Alex (1)").
  - The panel gets a "Borrow from" row linking to the card in their collection; owned cards say "Friends have" instead.
  - The deck page splits the wants that free copies don't cover into per-friend "Borrow from friends" checklists and "Nobody has these" (from the assembly plan's borrow and acquire lines).
  - The ledger shows "Friends have".
- **Display only:** there are no loans yet, so nothing moves.

**Deck notes** (`decks.notes`, the column from migration 0001, so no new migration): the owner's free-form context for a deck, such as its plan, budget rules, and why cards are in or out.
- **Web:** shown on the deck page as written (`white-space: pre-wrap`, autoescaped) with an owner-only edit form, `POST /decks/{id}/notes`, limited to `MAX_NOTES` characters. Empty text clears it.
- **Reading:** `GET /decks/{id}/notes.txt` serves the plain text, and `mtg deck-notes ID [--set FILE|-]` reads or writes it locally.
- **Privacy:** notes are private like money, so friends get 403. They're the place to keep a deck's context between chats. Read them before working on a deck and update them when decisions change; version notes stay the change log.

**Deck export** (`/decks/{id}/export`, linked as "Export" on every deck page, friends included; nothing in it is private): `queries.deck_exports(get_deck(...))` builds three kinds of text, each with Copy (clipboard API, else select) and a `/decks/{id}/export/{kind}.txt` download (`decklist`, `shopping`, `borrow-{friend id}`).
- **decklist:** "Commander"/"Deck" sections, front-face names, and `(SET) number` plus `*F*`/`*E*` for owned pinned copies. It round-trips through `importers/decklist_text.parse` (tested).
- **shopping:** what's still to acquire after friends' copies. It is the assembly plan's acquire list: wants minus the owner's free copies minus what friends have between them (`tests/test_assembly.py` checks they agree).
- **borrow-{friend id}:** each friend's borrow list.

**Collection import** (`importers/collection_csv.py`, migration 0007): a collection CSV becomes the target user's lots, one per copy, with no transaction.
- **Formats:** columns are matched by header alias, so ManaBox, Moxfield, Archidekt, or any CSV with a Name column works. `parse()` is all or nothing and raises `CollectionImportError` naming the line.
- **Money and metadata:** a USD purchase price becomes that copy's `allocated_cost_cents` through `parse_cents`. Other currencies, non-NM condition, non-English, and proxies go into `lots.notes`. `acquired_date` comes from the Added column, or today.
- **Resolving** goes through `scryfall.fetch_collection`, which answers exact identifiers (`id`, set + number) from the cache first; only misses go to the network.
  - **Only a Scryfall ID or set + number pins a printing.** A stale ID retries its set + number.
  - A name or fuzzy match (up to 10) sets the canonical name but leaves `scryfall_id`/`set_code`/`collector_number` NULL. So does not being found at all. Either way the lot goes to the printings queue. Never guess a printing here either.
  - The summary reports not-found names and the unpinned count. One import is capped at `MAX_COPIES`.
- **Writing:** everything resolves before anything is written, then one transaction writes the `collection_imports` row (UNIQUE `(owner_id, sha256)`, so a file imports once per collection) and the lots, each with `collection_import_id`.
- **Web:** the upload is `POST /people/{id}/import` (multipart, at most `MAX_UPLOAD_BYTES`, also checked against Content-Length before parsing). It's allowed by `may_act_for`: always into your own collection, and for others only via `users.can_act_for` in `dev`/`cloudflare` mode. Use `may_act_for` for every future act-for-a-friend route.
- **Duplicates:** the sha256 check only stops the identical file. A re-export with one more card would import everything again. There's no merge. Undo exists on the API only: `DELETE /api/v1/imports/{id}` (`services/collection.delete_import`, see "JSON API").

**Commander:** `mtgtracker/commanders.py` lets any legendary creature on a Commander-format deck's list be its commander, checked against the cached type line. The deck page has the picker (`POST /decks/{id}/commander`). There is one commander per deck, with no partners. A middleware rejects POSTs whose `Origin` doesn't match `Host`, or that carry `Sec-Fetch-Site: cross-site`. Write routes use POST, then a 303 redirect, with the notice or error passed as a query param.

**Printings** (`mtgtracker/printings.py`) is the backend for `/printings`. It pins unresolved lots (`scryfall_id IS NULL`) to a printing the user picks from the physical card.
- **Candidates** come from every `*.json` in `scryfall.CACHE_DIR`. Always read `CACHE_DIR` as a module attribute at call time so tests can patch it.
- **Groups:** lots are grouped by card name, finish, product, and current equipped deck (NULL-safe `IS`). A group is addressed by its lowest lot id.
- **Assigning:** `assign()` validates the name, the finish against the printing's `finishes`, the quantity (at most the group size), and that the lots are still unresolved. It writes nothing if any of these fail. It fills lots in ascending id order and upserts `scryfall_cards`. Picking a printing can change `lots.finish`.
- **Seeding stays honest.** Never auto-pick a printing in `precon_decklist.py`.

**Test fixtures** (`tests/conftest.py`): `db_path` is a copy of a session-scoped, seeded, file-backed DB. Seeding it fresh per test would take seconds on WSL because of per-card commits. `cache_dir` patches `scryfall.CACHE_DIR` to a temp copy of the fdc fixture, and makes any httpx request fail. Use `install_transport(monkeypatch, httpx.MockTransport(...))` to fake a Scryfall fetch. Web tests must use `cache_dir`, or requests would read the real gitignored cache.

**Scryfall:** `scryfall.py` fetches one whole set through the search API and caches it in `.scryfall_cache/<set>.json`, which is gitignored. Set fetches never make per-card calls. `fetch_collection` answers ids, set + number and names from the cache first; if the collection POST times out, fails to connect or returns 5xx, it resolves that batch with per-card GETs (0.3s apart, 429 back-off, 404 = not found) and raises the POST's own error only if Scryfall is unreachable. Tests must stay network-free: `test_precon_decklist.py` monkeypatches `scryfall.CACHE_DIR` to a temp dir seeded from `tests/fixtures/scryfall_fdc.json`.

**Seed decklists** (`seed/precon_decklists/*.json`) have the keys `deck_name`, `product_display_name` (must exactly match the cleaned product title), `format`, `commander`, `set_code`, `cards` (unique non-basic names), and `basics` (name → count). `cards` plus the `basics` counts must total 100. A test enforces this.

## Safety net

Write log, restore points and recovery: `db.py` (triggers, batch ids), migration 0009, `restore.py`, `recover.py`.
- **Write log:** `changelog(seq, at, batch_id, tbl, op, row_id, before_json, after_json)`. `migrate()` generates `cl_<table>_<i|u|d>` triggers for every table except `changelog`/`changelog_context`, with every column as JSON and `rowid` as `row_id` (so tables must stay rowid tables without BLOB columns).
  - It drops them before applying a migration (a table rebuild isn't logged row by row) and regenerates them after, writing one `S` row `{"user_version": N}` per migration. With nothing pending it compares the stored trigger SQL with what the current columns need, and rewrites only on a difference. Other triggers (`users_system_*`) are never touched.
  - A new table or column needs nothing: the next `migrate()` covers it. A cascade or `INSERT OR REPLACE` that deletes without firing triggers would be missed, since `recursive_triggers` is off. Don't use them on logged tables.
- **Batch ids:** `changelog_context` (one row) holds the batch id the triggers stamp on rows. A TEMP table can't be read by a main-schema trigger, and an application function would break every other client of the file (sqlite3 shell, the old release during a rolling update).
  - `db.connect` returns a `db.Connection` that sets the row just before the first INSERT/UPDATE/DELETE of a transaction and clears it just before every commit, so it never outlives one transaction or leaks to another connection. `db.set_batch(conn, id)` fixes an id; `db.set_batch_provider` calls a function at that moment.
  - The web uses the provider (`deps.reserve_audit`, wired in `get_conn` for non-GET requests): it inserts the request's `audit_log` row inside the same transaction, just before the first change, so `changelog.batch_id` = `audit_log.id`. A rolled-back request leaves neither. The identify middleware then only fills in the summary (`audit.finish`); a successful write that changed nothing still gets its row there (but never a dry run). A failure while reserving is logged and the write goes ahead untagged. The CLI and scripts write `batch_id` NULL. A JSON API dry run (`?dry_run=1`) installs no provider, so it reserves nothing.
- **Restore points:** `restore.take(db_path, action)` is an online backup, gzipped, to `<db dir>/restore/<UTC stamp>-<endpoint slug>.db.gz` with a `.json` sidecar (`changelog_seq`, `user_version`, `size`), written under temp names then renamed. `prune` keeps the 50 newest plus the newest of each UTC day, forever.
  - Web: `deps.reserve_audit` takes one just before a request's first change if the newest is over 10 minutes old (`restore.maybe_take`). A `@risky` route takes a forced one in `deps.run_risky`, except for a system actor's dry run. The point's name goes to `audit_log.restore_point`. A failed snapshot is logged and never breaks the request.
- **Recovery:** `recover.recover(point, log_db, out, until_seq|until_time|until_audit)` decompresses the point into a new file (refuses an existing one or the live DB), replays `changelog` rows after the point's seq with FKs off and the `cl_%` triggers dropped (`I` insert-or-replace by rowid, `U`, `D`, `S` runs `migrate(target_version, log=False)`), copies those log rows in with their seq, regenerates the triggers, and reports FK problems and row counts vs the live DB. The live DB is opened read-only, and a log whose row at the point's seq differs from the point's own is refused (a restore elsewhere reuses seq numbers). Put the result live with `deploy/minikube.sh restore`.
- **`recover.undo_batch(conn, audit_id, commit=True)`** reverses exactly that batch in reverse seq order and refuses if a later change touched any of its rows. The CLI does a dry run unless `--yes`. Not on the web yet.
- **Never `VACUUM`** a live DB: it can renumber implicit rowids (e.g. `deck_version_cards`), which replay and undo address rows by. Take a point right after one if it must happen.
- **Limits:** old-release writes during a rolling update's migration window go unlogged (triggers are dropped while a migration runs); `undo_batch` can't resurrect a row that an `INSERT OR REPLACE` replaced; a system actor's confirm that then fails still took its forced point.
- **Size:** each row change is a log row holding the whole row twice (an update) or once, so the log grows with writes, not with data. The seeded test DB logs every seeded row once.

## JSON API

`/api/v1` (`web/api/v1/`) is the same services and guards as the web pages, for scripts and the system user. The identity middleware covers it, so `request.state.user` is the principal; persons and system actors (`X-Dev-Service`/service token plus `X-Act-For`) both work. `GET /api/v1/openapi.json` is the OpenAPI document of the `/api/v1` routes only (behind sign-in; `/docs` stays off).
- **Errors** under `/api/` are always `{"error": {"code", "message", ...extra}}` with the right status, for any caller: 401 (also from the middleware), 403, 404, 405, 409, 422 (`validation_error`) and the cross-origin 403. Other paths keep their HTML/plain behavior. `ServiceError` becomes 422 `rejected`, `NotFoundError` 404, `UpstreamError` (Scryfall) 502, and a `CodedError` subclass its own `code`/`status`/extra fields.
- **Endpoints:** reads `GET /me`, `/decks[?owner=]`, `/decks/{id}` (cards one per lot with `lot_id`, wants, friends' copies, `pending_changes` for the owner only, `cost_cents` only on lots the principal owns), `/decks/{id}/notes` (owner only), `/decks/{id}/export/{kind}`, `/decks/{id}/versions/{v}`, `/cards/owners?name=A&name=B` (every owner's copies and where, no money), `/collection[?owner=]`, `/audit?limit=`, `/restore-points` (principal is an admin), `/people/{id}/imports`. Writes `POST /decks` (201, from list text), `POST /decks/{id}/changes`, `PUT /decks/{id}/notes`, `POST /decks/{id}/commander` (`{"name"}`, `{"lot_id"}`, or `{"name": null}` to clear), `POST /people/{id}/imports` (201; multipart `file` or JSON `{csv, filename}`; same limits and `may_act_for` rules as the web), `DELETE /imports/{id}`, `POST /purchases` (201), `DELETE /purchases/{id}`. Purchase reads: `GET /purchases[?source=manual]`, `GET /purchases/{id}` (see "Purchases").
- **`dry_run`:** `?dry_run=1` on any write runs the real service with `commit=False`, builds the response, then rolls back; the body is the real one plus `"dry_run": true` (and the same status). `deps.is_dry_run` is checked in `get_conn` (no batch provider, so no audit row, write-log batch or restore point), in the audit middleware (no row even though the status is 200), and in `run_risky`. Every write route goes through `common.write`.
- **`POST /decks/{id}/changes`** `{adds: [{name}|{lot_id}], cuts: [{lot_id}|{want_id}|{name}], note, expect_version}` is `services/modify.apply_batch`: it queues each add (a name is planned, a lot_id is owned), pairs `adds[i]` with `cuts[i]`, and applies one new version, all or nothing. More adds than cuts is fine; more cuts is 422 `pure_cuts_unsupported`. A stale `expect_version` is 409 `version_conflict` (with `current_version`), and a deck with Modify-page changes queued is 409 `pending_changes`; the API never applies someone's half-built queue. A name cut takes a wanted card first, then an owned copy that isn't physically in the deck, lowest id first, and never one an earlier cut took. The response gives `version`, `added`/`removed` names and the `counts` (here/away/wanted).
- **Assembly:** `GET /decks/{id}/assembly` (the plan) and `POST /decks/{id}/assembly` (+ `/assembly/pulls`, risky), see "Deck assembly".
- **Risky:** `DELETE /imports/{id}` is `@risky` and undoes a collection import (`services/collection.delete_import`): it deletes the import's lots and record, and refuses with 409 `import_in_use` (and `blockers`) if any lot is on a deck list, equipped, disposed, in a version snapshot or in any `deck_changes` row. Only the import's owner (the principal) may. A person just does it; a system actor gets 409 `confirm_required` with the preview and a token, and repeats with `?confirm=TOKEN`. `?dry_run=1` returns the preview to anyone with no token. A risky API operation returns `(notice, preview)`.
- **Script client** (`.claude/skills/mtg-deckbuilding/scripts/_api.py`): config from the environment, then the gitignored `.env` (parsed with `env_value`'s rules, never sourced): `MTG_BASE_URL` (required; the public site), `CF_ACCESS_CLIENT_ID`/`CF_ACCESS_CLIENT_SECRET`, `MTG_ACT_FOR` (default 1), `MTG_DEV_SERVICE`. It sends the service-token headers only when both halves are set and the base URL is HTTPS (never to a plain-HTTP rehearsal server), `X-Dev-Service` only when set, and `X-Act-For` only when the server identifies a system user: it asks `/me` once without it, because a site in single mode (or a rehearsal server) treats every caller as a person and refuses `X-Act-For` with 403. Secrets never come from argv or appear in errors. `ApiError` carries the API's code and message; `ConfirmRequired` carries `.preview`/`.token` and is never confirmed automatically.
- **Known quirks:** a system actor's request touches its credential's `last_used_at` in the identify middleware, so it logs a `service_credentials` change even on a dry run. A failed risky call or a failed write still took its restore point (the point is taken before the first change).

## Purchases

`mtgtracker/purchases.py` (plan, then record), `importers/cart_text.py` (parser), `services/purchases.py`, `web/api/v1/purchases.py`, `web/routes/purchases.py` (`/purchases/new`, `/purchases/preview`, `POST /purchases`), `mtg record-purchase`. No migration: `transactions.source = 'manual'` already existed.
- **Collection only.** A purchase adds a transaction, a product per line and one unassigned lot per copy to the principal's collection. It never touches a deck (tests compare `deck_cards`, `deck_wants` and `decks.version` before and after). `wanted_by` only points out, per deck of the principal's, how many new copies match its `deck_wants` (per distinct card `min(new copies, wanted copies)`, matched with `scryfall.name_keys`).
- **Formats** (`cart_text.parse`, all or nothing, `CartParseError` names the line): store CSV (`Card Name,Set / Edition,Rarity,Condition,Quantity,Price`, Price per copy), checkout paste (`Description Cond Qty Stock Price Total`, tabs or runs of spaces; Total must equal Qty x Price; "Set: Card" is split at the last colon, the other cuts are kept as `set_alternatives` for the resolver), and a plain list (`2 Name (Set, NM), $1.25`; the price is per copy, or a line total when followed by `total`; an optional `TOTAL: N items, $X subtotal` must match). A parenthetical or ` - Foil` / `*F*` suffix carries hints: collector number (`0064` strips to Scryfall's `64`), finish (etched before foil; "non-foil" is not foil), condition, treatments. A non-NM condition and treatments go to `lots.notes`.
- **Reconcile or raise.** Lines sum to the subtotal, and subtotal + tax + shipping must equal the total (`PurchaseError` gives the exact difference). Tax + shipping are split over line subtotals with `largest_remainder_split` into `products.tax_allocated_cents`; `allocation.allocate(commit=False)` splits each line's cost basis evenly over its copies.
- **Pinning is never guessed.** Every card must be found by name (`fetch_collection`, no fuzzy retries) or the whole purchase is refused (`cards_not_found` with `names`). A set name maps to a code through `scryfall.fetch_sets()` (cached at `CACHE_DIR/meta/sets.json`, not in the root: `cached_cards()` and the printings queue read every root `*.json` as cards), exact normalized match or with a trailing "decks" dropped; unknown or shared names mean no set. A printing is pinned only by set + collector number that Scryfall finds under the same card name, or by a fully cached `CACHE_DIR/<set>.json` holding exactly one printing of the card (an uncached set is never fetched to count), and only if it comes in the line's finish. Everything else keeps the name with `scryfall_id`/`set_code`/`collector_number` NULL for `/printings`, with the reason in the preview.
- **Preview writes nothing.** `purchases.plan()` only reads (and fills the Scryfall cache); `record()` writes. The web Preview POST sets `request.state.no_audit` so it leaves no audit row or restore point; the API uses `?dry_run=1` like every write.
- **Undo** is `DELETE /api/v1/purchases/{id}`, `@risky` (`services/purchases.delete_purchase`): only manual purchases, only the owner (others get 404), and 409 `purchase_in_use` if a lot is on a deck list, disposed, in a version snapshot or in a change (shared with import undo via `collection.lot_blockers`), or the transaction has receipts or deck costs. A person just does it; a system actor confirms the preview. There is no web button yet.

## Deck suggestions

`mtgtracker/suggestions.py`, migration 0010, `services/suggestions.py`, `web/routes/suggestions.py` (`/decks/{id}/suggestions`), `web/api/v1/suggestions.py`, the skill's `scripts/suggest.py`. Proposed cards to compare before anything changes.
- **Not on the list.** A `deck_suggestions` row is never a lot, a want or a change, so it stays out of counts, identity, breakdown, exports and assembly (tested). Owner only: reasons are deck strategy, so friends get 403 like notes.
- **Create** (`POST /api/v1/decks/{id}/suggestions`, `{suggestions: [{name, replaces?, reason?, theme?, price_cents?}]}`, 201) resolves every card with `fetch_collection` (cache first) or refuses the batch with 422 `cards_not_found` (`names`); a `replaces` must match a list entry by `name_keys` and is stored in the list's spelling. Cards already on the list, already suggested for the same slot, or dismissed before (any slot) come back in `skipped`. `suggested_by` is the actor. The price is the suggester's snapshot in cents; page loads never fetch.
- **State is derived:** `open`, `queued` (accepted and its `deck_changes` row is pending), `applied` (that change has an `applied_version`), `dismissed`. `change_id` has no foreign key: removing the change on the Modify page makes the suggestion open again.
- **Accept** queues a planned change (`deckmods.add_planned_card`, no Scryfall call) and pairs it with an entry for the cut card that no pending change already replaces (`deckmods.pick_cut`, shared with the API's name cuts). Nothing is applied from the page, and a queued change makes `POST /decks/{id}/changes` (and so `apply_list.py`) answer 409 `pending_changes` until it's applied or removed on Modify. **Dismiss** keeps the row (the "don't suggest again" memory); **Reopen** undoes it.
- **Page:** themes newest first; inside one, a slot per replaced card (the card on the list now, then each option with mana value and its change, type, price and reason), plain additions last; then "Decided". The deck page's action bar shows "Suggestions N" to the owner when any are open.

## Deck assembly

`mtgtracker/assembly.py` (`plan`, `apply`), `services/assembly.py`, `web/routes/assemble.py` (`/decks/{id}/assemble`, `.../assemble/preview`, `POST .../assemble`), `web/api/v1/assembly.py`, `mtg reassemble-deck`. No migration. This is the step purchases leave out: turn a deck's list into a physical deck from what the owner has.
- **Plan** (`plan(conn, deck_id)`, read-only): every list entry (`deck_cards` plus `deck_wants`) lands in one category: `here` (equipped here), `fill` (a want the owner has a free copy of), `swap` (an owned lot equipped in another deck, with a free copy of the same card), `pull` (equipped in another deck, no free copy; **risky**), `equip` (on the list, in no deck), `borrow` (a want a friend owns; display only, no loans), `acquire` (the rest; this is the shopping export). A disposed lot or another user's lot on the list is `plan.unavailable`, never acted on.
- **Free copy:** a non-disposed lot of the deck's owner on no deck's list at all (any `deck_cards` row) and not the `add_lot_id` of a pending `deck_changes` row. Matched by `scryfall.name_keys` (normalized name or front face). One copy fills one slot; wants are served before swaps. Preference: pinned to the want's `scryfall_id`, then any pinned, then unpinned, then lowest lot id. Basics count like any card.
- **Line ids** are stable strings: `fill:want:<id>:lot:<id>`, `swap:lot:<old>:lot:<new>`, `pull:lot:<id>`, `equip:lot:<id>`. Fills, swaps and equips are pre-checked; pulls never are. The plan also has `pull_list(line_ids)`: where to take each card from, grouped by other deck, then "your collection" (labelled "from Corner Games, 2026-10-20" via the lot's transaction, or the import).
- **Apply** (`apply(conn, deck_id, line_ids, note=, commit=)`) re-plans inside the transaction and refuses the whole request if any id isn't in the fresh plan (`AssemblyError.stale`; 409 `stale_plan` over the API). Fill deletes the want and adds the free lot equipped here; swap removes this deck's row for the away lot (it stays equipped and listed in the other deck) and adds the free lot equipped; pull and equip set `equipped` here (a pull unequips it elsewhere); nothing else in another deck changes. Money is untouched.
- **Version:** one new version, only when a fill or swap was applied, because only those change the snapshot (`deck_version_cards`/`deck_version_wants` hold lots and wants, not `equipped`). Default note "Assembled: N filled, N swapped, N pulled, N equipped". The version page shows the new lots and no +/- (diffs compare name multisets). A pull- or equip-only apply records no version (`version` is null).
- **Web:** the owner-only page lists each category (tiles with the shared panel, a checkbox per step), a Preview POST (writes nothing, no audit row; before/after counts and the pull list), then Assemble (303 to the deck page with the notice and `pl=` encoding the pull list, which the deck page shows as "Pull list" for the owner). The deck page's old reassemble block is a one-line summary linking to Assemble, plus the borrow and acquire checklists.
- **API:** `GET /decks/{id}/assembly` (plan, lines, `pull_list`, acquire/borrow). `POST /decks/{id}/assembly {line_ids, note}` applies fills/swaps/equips and answers 422 `use_pulls_endpoint` for a pull. `POST /decks/{id}/assembly/pulls` is `@risky` (needs at least one pull, else 422 `no_pulls`): a person just does it, a system actor confirms the preview with the token (bound to the same `line_ids` and `note`). Both take `?dry_run=1`; friends get 403. Pulls have their own endpoint because the risky registry expects every `@risky` route to always ask a system actor to confirm.

## minikube

`Dockerfile` plus `deploy/k8s/` (kustomize), driven by `deploy/minikube.sh`.
- **kubectl:** the script uses `kubectl` if installed, else `minikube kubectl --` (WSL often has only minikube). `start` brings an existing cluster back after a reboot (needs Docker running; it builds, applies and restarts nothing).
- **Image:** `pip install -e .` at `/app` on purpose. `SEED_DIR` and `scryfall.CACHE_DIR` resolve relative to the source tree, so a site-packages install would break seeding. The image is non-root, with a read-only root filesystem.
- **Storage:** one PVC at `/data` holds the DB, the receipts, and the Scryfall cache (mounted into `/app/.scryfall_cache` via `subPath`).
- **Deployment:** `replicas: 1`, with a zero-downtime `RollingUpdate` (`maxSurge: 1`, `maxUnavailable: 0`, readiness on `/healthz`, and a 5s `preStop` sleep so the old pod drains before it stops).
  - Two pods share the SQLite file for a few seconds. That's only safe because minikube is one node: RWO is per node, and SQLite locking works across processes on a local disk. Use `Recreate` on any multi-node cluster.
  - The new pod migrates while the old code still serves. Additive migrations are fine. Deploy a migration that rewrites or drops a table with `Recreate`. The image tag is `mtgtracker:dev` with `imagePullPolicy: Never`, built by `minikube image build`. `up` does a `rollout restart` to pick up a rebuild.
- **Access:** the Service is ClusterIP only, reached with `forward`, which binds 127.0.0.1. There is no NodePort or Ingress.
- **Cloudflare Tunnel:** optional, in `deploy/k8s/tunnel/`, and applied by `deploy/minikube.sh tunnel`, not by `up`. It's a remotely managed tunnel: the hostname and service URL (`mtgtracker.mtgtracker.svc.cluster.local:80`) live in the Cloudflare dashboard. The connector reads the tunnel token from the `cloudflared-token` Secret. The script creates it from, in order, piped stdin, `CLOUDFLARE_TUNNEL_TOKEN` in the gitignored `.env`, or a hidden prompt. `.env` is parsed by `env_value` and never sourced. Never put the token in argv or a tracked file. `.env` is also in `.dockerignore`. - **Sign-in on the cluster:** `up` writes the `mtgtracker-auth` ConfigMap from `.env`, with `MTG_AUTH` (default `single`), `CF_ACCESS_TEAM_DOMAIN`, `CF_ACCESS_AUD` and `MTG_OWNER_EMAIL`. The Deployment reads it with `envFrom` (optional). `apply_auth_config` refuses `dev` and refuses `cloudflare` without the domain and AUD, so a bad value fails the deploy instead of crash-looping the pod. Until `MTG_AUTH=cloudflare`, the public site has no sign-in, and the only write protection is the same-origin check on POSTs.
- **Moving data:** `load-db` and `pull-db` both take SQLite online-backup snapshots and move them into place under a temp name. Never copy the live file. The cluster DB is a separate copy that the UI writes to. `pull-db` keeps the old local file as `data/mtgtracker.backup-<timestamp>.db`, which is gitignored by `data/*.db`.
- **Keep data out of the image:** `.dockerignore` must keep excluding `data/`, `receipts/`, `.claude/`, and `tests/`. The scrubbed fixture still contains a card's last four digits.

## Sensitive data

Real `.order` files contain auth tokens and PII. `receipts/*` and `data/*.db` are gitignored. Only scrubbed fixtures (via `scripts/scrub_order.py`) belong in `tests/fixtures/`.
